# Specification

Implementation requires an approved contract containing:

- objective
- required behavior
- non-goals
- compatibility constraints
- acceptance criteria
- verification expectations

Repository facts MUST be distinguished from assumptions. Consequential unresolved decisions MUST be resolved before implementation.

A material requirement change invalidates affected approval until the contract is updated and re-reviewed.

Specifications MUST describe outcomes and constraints, not prescribe unnecessary implementation detail.
